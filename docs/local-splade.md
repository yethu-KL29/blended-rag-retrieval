# Local three-retriever implementation

The primary research path is local indexed BM25, ONNX MiniLM with FAISS, and optional pinned SPLADE. This supersedes the earlier enterprise-first decision in architecture-modes.md; its stored reports remain historical evidence. MongoDB/Gemini continues as an explicitly selected two-branch hybrid fallback. No automatic backend or model switching occurs.

BM25 stores weighted inverted postings as SciPy CSC matrices for combined text and each independent field. Its k1=1.5/b=.75 formula, tokenizer, lengths/IDF, field profiles and identifier formulation are unchanged. Queries visit only matching term postings; document filters precede top-k. Atomic manifests bind the complete ordered chunk contents, field definitions, format and scoring constants; payload SHA256, shapes and finite weights are checked on reload. Existing Counter statistics remain available for reference diagnostics. A stale or corrupt BM25 manifest is rejected; remove that manifest to explicitly rebuild from the current trusted dense store. Dense stores and FAISS assets are retained.

SPLADE is isolated in `blended_rag.sparse`; imports are lazy and base-only commands never require Torch. The provider calls actual sentence-transformers `SparseEncoder.encode_document`/`encode_query` on the pinned model, CPU with bounded batches/threads and max256 tokens. The document input is title + control ID + text. No training, normalization, alternate lookup or query substitution is used. `sparse-inspect` exposes learned query token dimensions and weights.

The independent `<store>/sparse` directory contains small CSR batch checkpoints, an assembled CSR matrix and an atomic `ready.json`. Identity includes format, full ordered source, count, model/revision, vocabulary dimensions, input representation, pooling and normalization. Each payload is hashed. Load checks count, vocabulary, sparse format, finite nonnegative values and source/model identity. Incomplete builds cannot replace the previous ready pointer. Different sources/models use different checkpoint generations; checkpoint-size changes start a separate checkpoint sequence. Failed inference preserves previously completed batches for restart. No corpus-by-vocabulary dense arrays are created; only N-document query scores are dense. Repeated ready indexing verifies integrity then reports unchanged.

Integrity failures are rejected rather than repaired silently. To rebuild a corrupt assembled sparse index, preserve a backup for diagnosis, remove its `ready.json` pointer and rerun `sparse-index`; valid matching batch checkpoints can be reused. If a checkpoint or its batch payload is itself corrupt, move the affected sparse directory aside and rebuild it from the trusted dense chunk store. Repeating indexing against the same corrupt ready pointer will continue to fail verification.

`lexical`, `dense` and `sparse` are direct branches. `hybrid` remains two-way weighted RRF with constant60 and bounded branch pools. `blended` fuses all three, requires positive sparse weight and a ready index, and skips zero-weight branches. Sparse-only supports zero lexical/dense weights. Deterministic ties use chunk ID; all branches filter metadata before top-k. Extractive answers preserve exact quoted source evidence, citations and hashes.

The `sparse-evaluate` command writes one completed report per method plus an atomic overall checkpoint containing pending/running/complete/failed status. All five methods use the same frozen queries/qrels, candidate pool100, control deduplication and existing Recall@10/MRR/NDCG/p95 protocol. It records first-call and warmed latency, build elapsed time, bytes, nnz, model bytes and external API cost0. First-call timings share a process and therefore include only loads not already performed by prior configurations; they are not independent fresh-process cold starts. Each failure is recorded and the CLI returns nonzero if any method is incomplete. No sparse default promotion follows from small seeds. Field profiles/formulation/weights remain explicit command options. Local and MongoDB results stay separate.

See README for exact setup, resume, query and evaluation commands. `RUN_CACHED_SPLADE_SMOKE=1 python -m pytest src/tests/test_sparse.py -k cached_real` gates a real-model smoke using cached weights only. Default tests use a clearly labeled fake encoder for deterministic sparse arithmetic, resume and corruption checks; these are not actual-model measurements. Full corpus throughput, offline cached inference and all-five measurements are recorded independently by the root verification workflow.

Model: NAVER SPLADE CoCondenser EnsembleDistil, revision `49cf4c7b0db5b870a401ddf5e2669993ef3699c7`, 30,522 vocabulary dimensions, CC-BY-NC-SA-4.0. Weights are not bundled in Git. Local CPU/storage costs are unpriced. Token truncation can discard evidence; learned sparse retrieval is not guaranteed to improve these small unvalidated qrels, and this implementation does not claim exact IBM replication.
